- **D-018  2026-10-06**  `Logger` (static, stderr + optional file) was written in Stage 2 instead of T5.3 because `DataCache` needs gap warnings. Indicators are grouped in one header/source (`Indicators.hpp/.cpp`) with a `PriceIndicator` intermediate base for close-only indicators.  |  Fewer files for a student-scale project.  |  yes
- **D-019  2026-10-06**  ATR: first bar's true range is high-low (no previous close); seed is the mean of the first n TRs. RSI returns 50 when both averages are 0, 100 when only the loss average is 0.  |  SPEC leaves these edge cases open.  |  yes
- **D-020  2026-10-06**  Backtester re-trades a slot only when its target weight changes; a constant weight is held, not re-balanced to `w * equity` every bar.  |  Re-balancing on every price move would charge fees for drift (and constant short weights would churn). SPEC sizing formula still applies at each change; toy-dataset numbers are unchanged.  |  yes
- **D-021  2026-10-06**  `MarketView(data, begin, index)` hides bars before `begin` as well as after `index`. `Backtester::run(data, from, to)` feeds up to `strategy.warmupBars()` earlier bars (decisions discarded) so test windows start with warm indicators but a flat portfolio. Unmentioned symbols in a strategy's output mean weight 0.  |  Gives strict rolling train windows and satisfies SPEC section 8 step 2.  |  yes
- **D-022  2026-10-06**  Trade episode P&L = cash after the exit fill minus cash before the entry fill (portfolio flat at both ends, so equity == cash). An episode still open at the window end is counted, marked at the final close, with `closed=false`.  |  SPEC defines episodes but not this edge.  |  yes
- **D-023  2026-10-06**  Breakout with `longShort=1` is stop-and-reverse (below the M-bar low goes short; above the N-bar high goes long). `ParameterGrid` lives in `research/` as in ARCHITECTURE; the strategy grids are stored in `StrategyFactory`.  |  SPEC leaves the short side of Breakout open.  |  yes
- **D-024  2026-10-06**  `DataCache::update` rebuilds a cache whose first bar is later than the requested history start (plus 2 intervals), because appending cannot extend history backwards.  |  Found when a 5-day cache silently stayed short after asking for 730 days.  |  yes
- **D-025  2026-10-06**  Pairs/Kalman z = the Kalman innovation standardised by its own rolling mean and std over `window` bars (like the OLS spread z), not `e / sqrt(Q)` alone. Kalman delta and Ve stay at the SPEC defaults (1e-5, 1e-3) and are exposed as params `kfDelta`/`kfVe`.  |  A diagnostic on real ETH/BTC data (no returns looked at) showed `e / sqrt(Q)` has RMS 0.086 and never exceeds 2 because Q >= Ve, so hedge=1 could never trade.  |  yes
- **D-026  2026-10-06**  Honesty test (SPEC test 14) uses seed 42 and passes with thresholds unchanged. Informational follow-up: over 20 other seeds, 10 of 180 noise rows were RECOMMENDED (5.6%), mean OOS Sharpe on noise is negative for every strategy, leakage test passes, so this is multiple testing, not leakage. Thresholds are NOT changed (D-011); the report prints the multiple-testing caveat.  |  Required by SPEC to log the outcome.  |  no
- **D-027  2026-10-06**  Pairs: hedge ratio is frozen at entry (weights do not change while a position is open); exit rule is "z back at or past -exitZ (long spread) / +exitZ (short spread)" because the literal `|z| < exitZ` can never fire for exitZ = 0; no entry when |z| already exceeds stopZ; beta <= 0 forces flat.  |  Avoids paying fees to re-hedge every bar and makes the exitZ=0 grid point meaningful.  |  yes
- **D-028  2026-10-06**  `BuyAndHold` weights are 1/numSymbols per symbol, so the baseline for a pair is a 50/50 long-only holding of both legs (single assets: weight 1). WF windows with no qualifying parameters are skipped and excluded from both the strategy and baseline stitched series. Unranked (INSUFFICIENT) rows get rank `-` in the CSV.  |  SPEC does not define the baseline for pairs.  |  yes
- **D-029  2026-10-06**  MLSignal details: 6 features per SPEC from closes only; training pairs are rebuilt from the visible train window; the live model is restored from the trained snapshot on `reset()`; with too few usable rows (< 50) the model stays neutral (all-zero weights) and never trades.  |  Keeps runs reproducible and leak-free.  |  yes
